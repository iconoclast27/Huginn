## How we work on this project

1. **Fixture-first verification.** Every meaningful behavior change should have a fixture in `src/fixtures/` (F01–F11 currently). Run `npm run typecheck && npm run fixtures` before declaring anything done.
2. **Test releases, not final releases.** In Huginn/Muninn we use `0.x.0-test.N` tags for BRAT smoke testing. Do not cut a new release for every tiny patch; batch fixes and ship when accumulated changes are worth testing.
3. **Docs are part of the change.** If docs are edited to explain or contextualize a code change, stage and commit them together.
4. **Muninn API is frozen.** Do not change `MuninnApi` shape without explicit user approval. All chat/skill UX lives in Huginn.
5. **BRAT release assets.** Huginn releases must attach `main.js`, `manifest.json`, `versions.json`, and `styles.css`. Muninn releases attach `main.js`, `manifest.json`, and `versions.json`.
6. **No force-pushing or rewriting published tags.** Tags are pushed to GitHub and used by BRAT; treat them as immutable.
7. **Use `gh release create` from the repo directory** with the required assets; avoid backticks in release notes passed through shell.
