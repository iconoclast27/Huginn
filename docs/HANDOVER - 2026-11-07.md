## How we work on this project

1. **Fixture-first verification.** Every meaningful behavior change gets a fixture. Run `npm run typecheck && npm run fixtures && npm run build` before declaring done. Current fixtures: F01–F18.
2. **Test releases.** Use `0.x.0-test.N` tags for BRAT smoke testing. Batch fixes and ship when accumulated changes are worth testing.
3. **Docs are part of the change.** Update `docs/TESTING1.md` and the harness doc when behavior changes. Commit docs with the code.
4. **Muninn API is frozen.** Do not change `MuninnApi` shape without explicit user approval. Huginn consumes it via `getMuninnApi()`.
5. **BRAT release assets.** Huginn releases must attach `main.js`, `manifest.json`, `versions.json`, and `styles.css`.
6. **No force-pushing or rewriting published tags.** Tags are pushed and used by BRAT; treat them as immutable.
7. **Use a notes file with `gh release edit --notes-file`** when release notes contain backticks or other shell-sensitive characters.
8. **Design docs before non-trivial refactors.** `docs/Ground Truth Refactor Design.md` was the model for the ground-truth refactor.
