## The Scenario F arc, in detail (the pattern to copy)

`docs/TestReport.md` recorded Scenario F as **FAIL**: Stop never aborts the in-flight request. Dan's fixture contract (2026-11-10) was implemented verbatim as `src/fixtures/f27.ts`:

1. Mock `fetch` drives an iteration process: **N=10** chunks.
2. The abort fires at predetermined iteration **M=3**, through the **fetch/controller channel only**.
3. The receptor asserted is **what the code should be**: the signal `fetch` was handed (`controller.signal`), not the external arg the buggy code listened to.
4. Abort not picked up → all 10 chunks consumed → **RED**.
5. Abort picked up → halts at 3 → **GREEN**.

Trap rules honoured: `reader.read()` **parks forever** once the queue drains (no natural stream end, so only abort detection can stop the loop); `cancel()` sets an assertable flag; `timeoutMs = 10_000_000` so the client's internal watchdog can never rescue the test; the fakes never reject on abort. Fixture-side watchdog 2000 ms declares RED when the loop never halts. Seam-integrity asserts run first. The client is typed `ChatLlmClient & LlmClient` so `complete(prompt, signal)` is called exactly the way `harness.ts:76` calls it, and `assert()` carries an `asserts cond` signature so guards narrow types.

**Two legs, because Scenario F is tested both ways:**
- **S1** — entry `chat()`, abort fired through the controller channel only (plain chat path).
- **S2** — entry `complete()`, abort fired through the user/external channel, the channel the chat view's Stop button actually uses (write-class skill path).

**Red, against committed `240b688`:**
```
npm run typecheck → clean, no import/mock error
npx tsx src/fixtures/f27.ts                                   exit 1
S1: chunks=10 (expected 3) cancel=false receptorAborted=true  result=PARKED
S2: chunks=10 (expected 3) cancel=false receptorAborted=false result=PARKED
F27 FAIL: S1: stream loop never halted — consumed 10 chunks, abort not detected inside the loop
```

**Second seam the contract did not cover (probe against committed code):** `OllamaChatClient.complete()` took **no** signal parameter and called `this.chat(messages)` without one, while `harness.ts:76` calls `complete(rendered.prompt, signal)`. Probe: `controllers recorded: 1`, `chunks consumed: 8 of 8`, `receptor aborted: false`, `cancel called: false`, `outcome: PARKED`. The Stop signal was dropped before the client built its controller, so the write-class leg had **no abort path at all** — passing `controller.signal` alone would not have made Scenario F pass for skills.

**The fix (two seams, `src/llm/client.ts` +8/-4):**
```
-    async complete(prompt: string): Promise<string | null> {
+    async complete(prompt: string, signal?: AbortSignalLike): Promise<string | null> {
-        return this.chat(messages);
+        return this.chat(messages, signal);

-            return await this.readStreamingResponse(res, signal);
+            return await this.readStreamingResponse(res, controller.signal);
```
`chat()`'s catch still classifies on the **external** `signal` (user Stop silent, timeout warns), so F26 behaviour is untouched. `fetch` is wired to `controller.signal` (line 85), which resolves the 11-10 note's **[UNVERIFIED]** question: in production the real `read()` rejects on abort, so a parked loop is bounded; the loop's top-of-loop poll covers aborts landing between reads.

**Green, official:**
```

S2: chunks=3 cancel=true receptorAborted=true result=null   exit 0
npm run typecheck → clean · npm run fixtures → F01–F27 GREEN · npm run build → main.js carries both seams
```

**Deliberately not in scope:** the 11-10 secondary finding — the abort flag is polled once per **chunk**, not per **line** (granularity gap) — is unchanged. A mid-chunk abort finishes processing that chunk's lines before the check; with `fetch` wired, that is bounded. Record it if it ever bites.

**Not certified:** the in-Obsidian experience (`[Interrupted]` bubble, approval modal closing on Stop, button returning to **Send**). `f27` guards the seam in `client.ts`; the UI leg (`chat-view.ts` `handleSend`/`runSkillFromChat`, which reads intact) has no automated fixture.
